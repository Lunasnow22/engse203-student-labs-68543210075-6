# B1 · บันทึกการแก้บั๊ก (กรอกให้ครบทั้ง 6 จุด)

> แต่ละบั๊กให้เขียน 4 อย่าง: ไฟล์ · บรรทัด · สาเหตุ (ทำไมทำงานผิด) · แก้อย่างไร
> เขียนด้วยคำของตัวเอง — จุดนี้จะถูกถามใน oral

## บั๊กที่ 1 — อาการ: Console เตือนสีเหลืองเรื่องรายการ
- ไฟล์/บรรทัด:ไฟล์/บรรทัด: src/components/RequestList.jsx (หรือจุดที่มีการใช้ .map() สร้าง RequestCard)
- สาเหตุ:สาเหตุ: React จำเป็นต้องใช้ prop key ที่ไม่ซ้ำกันเวลานำอาร์เรย์มาวนลูปเรนเดอร์ เพื่อติดตามการเปลี่ยนแปลงของ DOM แต่ในโค้ดไม่ได้ใส่ไว้
- แก้อย่างไร:แก้อย่างไร: เพิ่ม key={request.id} เข้าไปที่คอมโพเนนต์ <RequestCard ... key="{request.id}"/> ภายในลูป .map()

## บั๊กที่ 2 — อาการ: ตัวเลข "รอดำเนินการ" ในแผงสรุปไม่ตรงกับที่เห็น
- ไฟล์/บรรทัด:ไฟล์/บรรทัด: src/pages/DashboardPage.jsx (ส่วนการคำนวณแผงสรุป Summary)
- สาเหตุ:สาเหตุ: โค้ดส่วนที่นับจำนวนคำร้อง "รอดำเนินการ" ดึงค่าสเตตัสผิดพลาด (เช่น ไปนับ 'in-progress' หรือพิมพ์คำผิด) ทำให้ได้ตัวเลขไม่ตรงกับข้อมูลจริงที่มีสถานะเป็น 'pending'
- แก้อย่างไร:แก้อย่างไร: แก้ไขเงื่อนไขใน .filter() ให้ตรวจสอบสถานะที่ถูกต้อง คือ requests.filter(req => req.status === 'pending').length

## บั๊กที่ 3 — อาการ: กดตัวกรอง "รอดำเนินการ" แล้วได้รายการที่ไม่ใช่
- ไฟล์/บรรทัด:ไฟล์/บรรทัด: src/pages/DashboardPage.jsx (ส่วนฟังก์ชันจัดการ Filter)
- สาเหตุ:สาเหตุ: ปุ่มกรองหมวดหมู่ส่งค่าสถานะ (Status) ผิดไปให้ฟังก์ชันกรอง หรือเงื่อนไขในฟังก์ชันเช็คค่าผิด (เช่น เช็คเป็น !== หรือพิมพ์ค่า 'pending' ผิด)
- แก้อย่างไร:แก้อย่างไร: ตรวจสอบและแก้ไขค่าที่ปุ่มส่งไป (onClick) ให้เซ็ตค่าสเตตการกรองเป็น 'pending' อย่างถูกต้อง และให้เงื่อนไขการกรองตรงกัน

## บั๊กที่ 4 — อาการ: เปลี่ยน URL จาก REQ-001 เป็น REQ-002 แล้วข้อมูลไม่เปลี่ยน
- ไฟล์/บรรทัด:ไฟล์/บรรทัด: src/pages/RequestDetailPage.jsx (ส่วนการดึงข้อมูล useEffect)
- สาเหตุ:สาเหตุ: Hook useEffect ที่ใช้ดึงข้อมูลคำร้องมาแสดง ขาดตัวแปรพารามิเตอร์ (Dependency) ในวงเล็บเหลี่ยม [] ทำให้มันทำงานแค่ครั้งแรกครั้งเดียวตอนเปิดหน้าเว็บ และไม่ยอมดึงข้อมูลใหม่เมื่อ URL id เปลี่ยน
- แก้อย่างไร:แก้อย่างไร: เติมตัวแปร id ลงใน Dependency Array ท้าย useEffect ให้กลายเป็น [id] เพื่อบังคับให้ฟังก์ชันทำงานใหม่ทุกครั้งที่รหัสอ้างอิงเปลี่ยน

## บั๊กที่ 5 — อาการ: กด "ลบ" แล้วรายการยังอยู่ ต้องรีเฟรชถึงหาย
- ไฟล์/บรรทัด:ไฟล์/บรรทัด: src/pages/DashboardPage.jsx (ฟังก์ชัน handleDelete หรือ onDeleteRequest)
- สาเหตุ:สาเหตุ: โค้ดทำการลบข้อมูลออกจาก Local Storage หรือ Service แล้ว แต่ลืมสั่งอัปเดตสเตต (State) ของ React (requests) ทำให้หน้าจอไม่ยอมเรนเดอร์ใหม่
- แก้อย่างไร:แก้อย่างไร: เพิ่มคำสั่งอัปเดตสเตตหลังจากลบเสร็จ เช่น setRequests(prevRequests => prevRequests.filter(req => req.id !== id))

## บั๊กที่ 6 — อาการ: กด "Reset Demo Data" แล้วหน้าพัง/ว่างเปล่า
- ไฟล์/บรรทัด:ไฟล์/บรรทัด: src/pages/DashboardPage.jsx (ฟังก์ชัน handleResetData)
- สาเหตุ:สาเหตุ: ฟังก์ชันรีเซ็ตข้อมูลอาจจะคืนค่ากลับมาไม่ถูกต้อง (เช่น เป็น undefined) หรือลืมนำชุดข้อมูลที่รีเซ็ตแล้วกลับมาใส่ใน setRequests ทำให้เมื่อ React นำไป .map() จึงเกิด Error จนหน้าพัง
- แก้อย่างไร:แก้อย่างไร: ตรวจสอบการเรียกใช้ Service รีเซ็ตข้อมูล และดึงข้อมูลชุดใหม่มาอัปเดตสเตตให้ถูกต้อง เช่น requestService.resetData(); setRequests(requestService.getRequests());
